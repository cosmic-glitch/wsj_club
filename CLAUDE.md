# WSJ Reading Club

A daily reading-handout website for a small club of four kids in US grades 8–10. Each day = one Wall Street Journal article turned into a study handout with two sections — **Words to know** and **Concepts behind the story** — plus a **self-quiz** on its own page. Goal: build general knowledge, vocabulary, and conceptual understanding.

Live: https://wsjclub.vercel.app · Repo: https://github.com/cosmic-glitch/wsj_club

## Architecture

Next.js app (App Router, Next 16, React 19, Tailwind v4). The daily content is **data, not code**: one JSON file per day in `content/`. The content pages (index, handout, quiz) are **statically generated** — adding a day = adding one JSON file. The **voice-quiz feature** (see below) adds a handful of **dynamic server routes** (login, token minting, report card) and an admin page, so the app is no longer purely static, but every content page still prerenders.

```
content/YYYY-MM-DD.json           one file = one day's handout
public/pdfs/YYYY-MM-DD.pdf        served PDF of that day's article (the "PDF" link)
PDFs/                             manual-fallback drop-zone for raw WSJ PDF exports (gitignored)
article-text/YYYY-MM-DD.txt       gitignored drop-zone for full article plain text → uploaded to Blob (voice quiz)
app/page.tsx                      index: a compact row-list, one row per day (date + title, then a text-link action bar: article · handout · voice quiz)
app/reading/[date]/page.tsx       one day's handout — words + concepts, then a "Take the self-quiz" CTA at the bottom
app/reading/[date]/quiz/page.tsx  that day's self-quiz, on its own page (linked from the bottom of that day's handout)
app/admin/page.tsx                teacher-only (ADMIN_USERS) list of saved voice-quiz transcripts + report cards + audio playback (+ a Delete button per session)
app/api/login|logout|me/route.ts  password login → signed cookie; /me reports login + admin state
app/api/realtime-session/route.ts mints the OpenAI Realtime ephemeral key (login-gated)
app/api/quiz-audio/route.ts       mints an auth-gated client-upload token (handleUpload) so the browser uploads the recording straight to Blob
app/api/quiz-report/route.ts      grades a finished transcript → report card, saves to Blob (incl. audio link)
app/api/quiz-session/route.ts     DELETE a saved session (admin-only): removes its JSON + audio blobs
components/Quiz.tsx                interactive client-side self-quiz
components/DeleteSessionButton.tsx admin Delete button (client) → DELETE /api/quiz-session → router.refresh()
components/VoiceQuiz.tsx           the home-page "Voice quiz" launcher — button + modal WebRTC voice client
components/VoiceQuizStep.tsx       index row's login-gated "voice quiz" action-bar item (hidden until someone logs in)
components/AuthControl.tsx         header login/logout control (+ admin link for teachers)
lib/content.ts                    content types + loader + date helpers (the schema)
lib/auth.ts                       login auth + teacher/admin check (ADMIN_USERS): bcrypt verify + signed-cookie helpers
lib/quiz-prompt.ts                builds the tutor's instructions + report prompt from a day's content (+ full article text)
lib/article-text.ts               reads a day's full article plain text from Vercel Blob (null → handout-only)
scripts/hash-password.mjs         CLI: bcrypt-hash logins -> base64 AUTH_USERS value
scripts/upload-article-text.mjs   CLI: upload a day's full article text to Blob for the voice quiz
.claude/skills/wsj-pick-article/  the skill that scouts wsj.com and recommends the day's candidates
.claude/skills/wsj-reading/       the skill that produces a day's content
```

## Content schema (`lib/content.ts`)

A `Reading` = `{ date, title, articleUrl?, pdfUrl?, articles?, voiceQuiz?, source?, vocab[], concepts[], quiz[] }`.

- **articleUrl** — the WSJ web article (the **Web** link). **pdfUrl** (optional) — a served PDF of the article, e.g. `/pdfs/2026-06-09.pdf` (the **PDF** link); omit it and only the Web link shows.
- **voiceQuiz** (optional `boolean`) — when `true`, the home-page row for that day shows the AI-oral-quiz launcher as a login-gated item in its action bar. The skill sets `voiceQuiz: true` on every new day. It is now set on **every day** — the earlier pre-feature days (2026-06-09 → 2026-06-17) were backfilled, so all entries have the voice quiz for logged-in users.
- **articles** (optional) — for **multi-article days**: bundle two or more short articles into one combined handout. It's an array of `Source` = `{ title, articleUrl, pdfUrl? }` (each article's own headline + links). When `articles` is set, the top-level `articleUrl`/`pdfUrl` are unused, the vocab/concepts/quiz are **combined** across all the articles, and each article gets its own PDF named `/pdfs/YYYY-MM-DD-1.pdf`, `-2.pdf`, … (see `content/2026-06-14.json` for the first one). Most days are single-article and just use `articleUrl`.

- **vocab** — exactly **3** `VocabWord`s, each presented *article-first*:
  `articleQuote` (short real quote from the article) → `inContext` (what it means there) → `meaning` (broader definition) → `examples` (exactly **2** more example sentences).
- **concepts** — 3–5 `Concept`s, same article-first shape:
  `articleQuote` → `inContext` → `meaning` (how it actually works).
- **quiz** — exactly **5** `QuizQuestion`s, each `{ question, options (4), answerIndex (0-based), explanation }`.

Pages stay minimal. The **index** is a **compact row-list, one row per day** (a `<ul>` inside a single bordered card, hairline `divide-y` between rows, newest first). It replaced the earlier tall "one box per day" cards: those were ~8 lines each and scrolled badly as the list grows. The design intent was a **table**, but a literal `<table>` was rejected — a table shares column widths across all rows, so one long headline squeezes the action columns and forces **horizontal scroll on a phone** (the same problem that had earlier killed a six-column table). The row-list gets table-like compactness *without* that: each row's action bar simply **wraps** to a second line on narrow screens instead of scrolling. Each row is the **date** (a muted serif label, `dateBig`) + the **article title** as plain text (**not** a link) on one prominent line, then a small **action bar** of text links separated by middots (`·`): **Article** — the mobile-aware `ArticleLink`, with a "(PDF)" link right after it when `pdfUrl` is set; multi-article days (when `articles` is set) show "Article 1 (PDF) · Article 2 (PDF) · …", one per source; then **Handout**; then, login-gated, **Voice quiz**. There is **no self-quiz and no 1-1-quiz (Calendly) link on the index** anymore — the self-quiz moved to a CTA at the **bottom of each handout** (`/reading/<date>/quiz`, every day has one), and the Calendly 1-1-quiz link was dropped from the index entirely (it is no longer linked anywhere). The **Voice quiz** is a small client component, `components/VoiceQuizStep.tsx`: it's one more middot-separated action-bar item that **brings its own leading `·`** and reads `/api/me`, rendering nothing until a session exists — so signed-out visitors (kids just browsing) see only Article/Handout with no dangling separator, and it shows only for days with `voiceQuiz: true`. (The launcher button in `VoiceQuiz.tsx` is styled as a text link so it sits inline in the bar.) The handout top is **just the article title** (no date), then the two sections, then the **"Take the self-quiz →" CTA**. **Navigation is deliberately sparse:** the WSJ article link lives only on the index (in each row's action bar), and the only "← All readings" link is the one in the global header bar (`app/layout.tsx`, rendered via `components/AllReadingsLink.tsx`, which **hides it on the home page** — where it's redundant — and shows it on every other page) — content pages (handout, quiz) carry no inline back-link of their own. No summary/blurb, no reading-time estimate. In both vocab and concept cards the quote is labeled **"Quote from the article"**, followed by **"What it means here"** (in the article) and **"In general"** (the broader meaning).

## Voice quiz (beta)

A "Voice quiz" feature that automates the teacher's 1-1 oral quiz: a student clicks the **Voice quiz** link in that day's row on the home page and an AI tutor (OpenAI **Realtime API**, speech-to-speech over **WebRTC**) quizzes them aloud about that day's article in a modal, then a report card is generated and saved. **The student does not see the live transcript or the full report card** — but at the end they ARE shown their **overall score** (just the number, e.g. "8/10") plus an invitation to retake the quiz if they're not happy with it. The transcript, the full report card, and an **audio recording of the whole conversation** are captured to Blob and reviewed by the teacher on `/admin` (the live screen tells the student the quiz is recorded). The whole **voice-quiz action is hidden until someone logs in** (so signed-out kids never see it — `components/VoiceQuizStep.tsx`), and it shows only for days with `voiceQuiz: true`. It is the **last item in the day's action bar** ("Article · Handout · Voice quiz"). (The **Schedule your 1-1 quiz** Calendly link that used to sit beside it was removed from the index; the voice quiz is now the only on-page quiz option.) Clicking the voice quiz while logged out still pops up a "You need to log in" message rather than starting (a safety net for an expired session).

- **Auth gates it.** The whole site is public to browse, but starting a quiz requires login (a header **Log in** control). This is what stops the public from running up OpenAI charges. Credentials live in the `AUTH_USERS` env var: **base64-encoded JSON `{ username: bcryptHash }`**. Passwords are stored only as **bcrypt hashes** (bcryptjs, 10 salt rounds — same scheme as the foliotracker project), never plaintext, never in source; if `AUTH_USERS` is unset there are no users and **nobody can log in (fail closed)**. (Base64 because bcrypt hashes contain `$`, which Next's `.env` loader would expand.) Generate/extend the value with `node scripts/hash-password.mjs <user> <password> …` and set it as the env var. Login sets a signed httpOnly cookie (HMAC with `AUTH_SECRET`). To onboard the four real students, just regenerate `AUTH_USERS` with their names/passwords — no code change. `lib/auth.ts` is the auth core; `app/api/login|logout|me`.
- **The flow** (`lib/quiz-prompt.ts`, `buildInstructions`): greet by name (take your time) → ask the student to retell the article's **key ideas** from memory, **drawing out more** with open "Anything else? Any other ideas?" nudges until they've covered enough → **vocabulary** (meaning or use-in-a-sentence for each of the 3 words) → a few **concepts** from the handout → short encouraging wrap-up that ends by telling the student, word for word, "The quiz is done. You can press the End Quiz button." (the student then clicks **End quiz** to close — there is no auto-end). The day's vocab/concept *meanings* are injected as the tutor's answer key. A high-level **style guide** (Socratic, one question at a time, hint-don't-reveal, stay on-article, **patient listening — never interrupt**, and **"coach the gaps"** — whenever the student is wrong or half-right on an idea/word/concept, **ask a guiding follow-up question first** and only *tell* them the correct version if they still don't get it after that) lives in `STYLE_GUIDE` in that file — tune it there.
- **Full article text (the tutor's reference).** When available, the tutor is given the **whole article as plain text** (plus the full handout), so on the key-ideas step it *listens to the student's entire from-memory retelling without interrupting*, then judges it against the real story — accepting imperfect recall but expecting a few non-obvious points beyond the headline, and only probing afterward. The text is **not committed** (CLAUDE.md hard rule: never republish article text); it lives in **Vercel Blob** at `article-text/<date>.txt` (`lib/article-text.ts` reads it; `getArticleText` returns null → handout-only fallback for days without it). Upload it with `pdftotext public/pdfs/<date>.pdf article-text/<date>.txt` then `node --env-file=.env.local scripts/upload-article-text.mjs <date>` (the `/article-text/` dir is a gitignored drop-zone). This upload is now **part of the wsj-reading skill** (step 3), so every new day gets it. The earlier days were all backfilled too — from their captured PDFs (06-09/10/11/12/15/17, plus the two-article 06-14 concatenated), the Paul Graham essay page (06-13), and the original economist.com article (06-16, fetched with the user logged in, since its `archive.ph` link is CAPTCHA-walled). So **every day has full article text** in Blob.
- **Not interrupting / responsiveness.** Turn-taking is enforced at the transport: `app/api/realtime-session` sets `turn_detection: { type: "semantic_vad", eagerness: "auto" }` (env: `REALTIME_VAD_EAGERNESS` — `low`/`medium`/`high`/`auto`), OpenAI's setting for letting the speaker finish through pauses/ums rather than cutting in on silence. Default was `low`, but uniform `low` felt sluggish on short vocab/concept answers (the tutor held the turn open too long); switched to `auto` so OpenAI adapts — snappy on short turns, still patient on the long key-ideas retelling.
- **How it connects.** `components/VoiceQuiz.tsx` (client) renders the **Voice quiz** launcher (a link-styled button) as the home-page row's voice-quiz action-bar item (wrapped by `components/VoiceQuizStep.tsx`, which login-gates it). It reads login state from `/api/me` on mount (login/logout reload the page, so it stays fresh). On click: logged out → a "You need to log in" modal; logged in → it opens the modal and immediately uses the **login username** as the student name, POSTs to `app/api/realtime-session` (which checks login, builds the instructions — pulling the day's full article text from Blob when present — and mints a short-lived OpenAI **ephemeral key** — the real `OPENAI_API_KEY` never reaches the browser), then opens a WebRTC session straight to OpenAI. The transcript is captured silently (never shown to the student). **The quiz ends when the student clicks the End quiz button** — the only way to finish. The tutor's spoken wrap-up tells them to press it ("The quiz is done. You can press the End Quiz button."), so the close is fully manual; a once-guard makes `end()` idempotent against a double-click. (An earlier design had the tutor call an `end_quiz` tool to auto-close after its goodbye audio finished, but it was unreliable, so the tool and all the auto-end machinery were removed.) On End quiz it POSTs the transcript to `app/api/quiz-report`, which grades it into a report card (a text model, also given the full article text) and saves the whole session (transcript + report + audio link) to **Vercel Blob** under `quiz-sessions/<date>/`; the route returns the report, and the client reads only its `score` to show the student (e.g. "You scored 8/10") along with "saved for your teacher" and a "feel free to take the quiz again" invitation — the rest of the report card stays private. **After "End quiz" there is a single, stable wrap-up screen** (phase `wrapup`) — no screen-swap — with a checklist that fills in place: **Uploading your recording** → **Grading your quiz** (each a pending/active/done step with a ✓), and then, once everything is saved (`finished`), the **score line** appears below and the **Close** button enables. This replaced an earlier two-screen flow ("ending" → "done") whose statuses flashed by too fast to read; now nothing auto-advances — the student reads it and clicks Close. **Only the student's own turns are gradable:** the route counts the transcript's `student`-role turns and, if there are none (e.g. the student ended the quiz before speaking — the transcript can still be non-empty because it holds the tutor's greeting), it **skips the model entirely** and records an honest `score: "—"` "no answers to grade" card rather than letting the grader invent a score from the reference article. The grading prompt is also explicit that it must grade ONLY what the student actually said and never inflate a thin transcript (a previous bug let a no-speech session score 8/10).
- **Audio recording.** Both sides of the conversation are recorded with **no separate mechanism** — the student's mic and the tutor's remote track are already live `MediaStream`s in the browser, so `VoiceQuiz.tsx` mixes them with the **Web Audio API** (two `MediaStreamSource`s → one `MediaStreamDestination`) and runs a **`MediaRecorder`** over the mix (webm/opus on Chrome/Firefox, mp4 on Safari; ~0.5–1 MB for a typical quiz). The remote track is still played to the student through the hidden `<audio>` element (which keeps the track live so Web Audio actually receives samples; the recording graph only feeds the recorder, not the speakers). On "End quiz" the recorder is stopped first to capture the full Blob, which is uploaded **directly from the browser to Vercel Blob** via the `@vercel/blob` client `upload()` flow — **`app/api/quiz-audio`** only mints a short-lived, login-gated client-upload token (`handleUpload` / `onBeforeGenerateToken`), so the audio bytes never pass through the serverless function. (This replaced an earlier `multipart/form-data` POST through the route, which **413'd on full-length recordings**: routing the file through the function hit Vercel's ~4.5MB request-body limit, so a real quiz's recording was silently dropped while tiny test recordings squeaked under. The client upload has no such limit.) The returned blob URL is then passed to `app/api/quiz-report` and stored as `audioUrl` on the session JSON. The whole recording path is **best-effort** — if it can't start, upload, or save, the transcript + report still save and the quiz is unaffected. (Recording **minors' voices** is a heavier privacy step than the transcript; the live screen discloses it.)
- **Reviewing results (teacher-only).** `/admin` lists every saved session newest-first with score, report card, an inline **audio player** (when a recording was saved), and clickable (expand-to-read) transcript. The session JSON and the audio recording share the same `quiz-sessions/<date>/` prefix, so the listing **fetches only the `.json` blobs** (never tries to `JSON.parse` a `.webm`/`.mp4`), and each parse is independently guarded so one corrupt blob can't blank the page. It's gated to teachers by the **`ADMIN_USERS`** env var (comma-separated usernames; each must also be a login in `AUTH_USERS`). If `ADMIN_USERS` is unset, **nobody is an admin (fail closed)** — students who log in for the voice quiz can't reach it. An **Admin** link appears in the header only for admins (`/api/me` returns `isAdmin`). Onboard yourself by adding your username to both `AUTH_USERS` (via `scripts/hash-password.mjs`) and `ADMIN_USERS`. Each session has a **Delete** button (`components/DeleteSessionButton.tsx`, a client component in the card's header) that confirms, then calls `DELETE /api/quiz-session` with the session's blob URL (and its `audioUrl`) and `router.refresh()`es the list. The route is **admin-gated** and `del()`s both blobs, refusing any URL not under the `quiz-sessions/` prefix; the page attaches each JSON blob's `url` as `blobUrl` at load time (it isn't part of the saved session JSON).
- **Models/voice** are env-overridable in case OpenAI renames them: `REALTIME_MODEL` (default `gpt-realtime-2`), `REALTIME_VOICE` (default `cedar` — a male voice; `cedar`/`marin` are OpenAI's two top-quality voices, others: `ash`/`echo`/`ballad`/`verse` male-ish, `marin`/`coral`/`shimmer`/`sage` female-ish, `alloy` neutral), `REPORT_MODEL` (default `gpt-5.4-mini` — the grader; verified working with our chat/completions + `response_format: json_object` request this build. Was `gpt-4o-mini`, bumped because that model is two generations behind; the grading is a judgment task, so a current model matters. Volume is tiny — a few short transcripts a day — so cost is negligible; set `REPORT_MODEL=gpt-5.4` for the full model if you ever want stronger judgments), `REALTIME_VAD_EAGERNESS` (default `auto`). The `gpt-realtime-2` model, `semantic_vad`, and the `cedar` voice were confirmed working against OpenAI's API this build. Beyond voice choice, **delivery (tone, pace, warmth) is steered through the tutor's instructions** (`STYLE_GUIDE`), not a separate API knob; there's no speed parameter and **no voice cloning** (can't use a custom/your-own voice).
- **Status (beta, still testing).** The backend is verified end-to-end on both local and production: login, ephemeral-token minting (OpenAI accepts `gpt-realtime-2` + `cedar`), report-card generation (now `gpt-5.4-mini`), Blob save, and `/admin` listing all work. It's smoke-testable without a browser by POSTing to `/api/login` then `/api/realtime-session` (and `/api/quiz-report` with a fake transcript). A first in-browser run surfaced (and fixed) a bug where the saved **audio recording** broke `/admin`: the recording and the session JSON share the `quiz-sessions/<date>/` prefix, and the admin listing was `JSON.parse`-ing every blob — so the first `.webm` made the whole page show "Could not load sessions." Fixed by fetching only `.json` blobs (see *Reviewing results*). A later in-browser run then exposed a second recording bug: a full-length quiz's recording came back missing on `/admin`, and the runtime logs showed `/api/quiz-audio` returning **413** — the old `multipart/form-data` POST routed the audio through the function and hit Vercel's ~4.5MB request-body limit (short test recordings had squeaked under it). Fixed by switching to the `@vercel/blob` client `upload()` flow (browser → Blob direct; the route only mints a token), so size is no longer a constraint. The tutor-driven auto-end (`end_quiz` tool) proved unreliable and was **removed** — the quiz now ends only when the student clicks **End quiz**, which the tutor tells them to do. **The pieces still being shaken out are the in-browser microphone → tutor-audio WebRTC round-trip and the rest of the audio-recording path** (mic+tutor mix → `MediaRecorder` → client `upload()` → playback on `/admin`) — confirm those in a real browser: log in, then on the home page click **Voice quiz** in today's card, finish a quiz (let the tutor wrap up, then click **End quiz** when it tells you to), and check `/admin` for the report card and a playable recording. Logins are `anurag` (also the `/admin` teacher) plus the four students `anusha`, `samaira`, `arjun`, `mehar` (passwords are NOT stored in the repo — rotate/add users via `scripts/hash-password.mjs`). The logged-out "You need to log in" popup was browser-verified on the earlier table UI.

## Daily workflow

Two skills, two steps, with the user as the validation layer between them:

1. **`wsj-pick-article`** — run first each day ("pick an article", "what should we read today"). Checks `content/` for recently covered domains (quality and learning value come first; variety across days is a preference, used as a tiebreaker), browses **both the wsj.com and economist.com homepages** (pooling candidates across the two sources — the source is just a label on each pick; **if either site looks logged-out or paywalled it stops and asks the user to log in** before continuing, since The Economist hard-paywalls logged-out readers), verifies candidates are substantive text articles you can read in full (not video-led pages, live blogs, or chart-only stubs), and recommends a ranked top pick plus 2–3 runners-up. It only recommends — the **user** checks the suggestions and picks one.
2. **`wsj-reading`** — invoked with the chosen link (or when the user pastes any WSJ link / says "today's reading"). It reads the article in the browser (the user logs into WSJ themselves), then **proposes the 3 vocab words and 3–5 concepts and waits for the user's explicit go-ahead before generating anything** (a manual quality gate — the selection is discussed and revised first), writes `content/YYYY-MM-DD.json` (with `voiceQuiz: true` so the day's voice quiz is live), **captures the day's PDF directly from the open page** (`page.pdf()` → `public/pdfs/YYYY-MM-DD.pdf`, setting `pdfUrl`; the `PDFs/` drop-zone is now only a manual fallback) — capturing **text-focused** (isolate the `<article>`, drop images, `printBackground:false`) so the file stays ~100KB rather than tens of MB, because Chromium's print path otherwise embeds every photo at full `srcset` resolution (the SKILL.md has the exact snippet) — **uploads the full article text to Blob** (`pdftotext` → `scripts/upload-article-text.mjs`, so the tutor gets the whole article) — then builds, commits, and pushes (which deploys).

Audience calibration lives in both skills; the article-first content rules live in `.claude/skills/wsj-reading/SKILL.md`. Hard rule: link to WSJ and quote only short phrases — never republish the article text.

## Deploy

GitHub `cosmic-glitch/wsj_club` (public) → Vercel project `wsj_club` (team *Anurag's projects*). **Push to `main` auto-deploys to production** at `wsjclub.vercel.app` — no manual `vercel --prod` needed. `npm run build` validates every content JSON locally.

**Env vars** (for the voice quiz — set in Vercel project settings, and locally in the gitignored `.env.local`): `OPENAI_API_KEY` (required), `AUTH_USERS` (base64 bcrypt logins — see Voice quiz above; no login works without it), `AUTH_SECRET` (a long random string), `ADMIN_USERS` (comma-separated usernames allowed into `/admin`; **set this to your own username** or no one can see the report cards — fail closed), `BLOB_READ_WRITE_TOKEN` (auto-added when a Vercel Blob store is linked; `vercel env pull` to get it locally), and optionally `REALTIME_MODEL`, `REALTIME_VOICE`, `REPORT_MODEL`. The voice quiz is inert (returns a clean error) until `OPENAI_API_KEY` is set; saving to Blob is best-effort and won't break a session if `BLOB_READ_WRITE_TOKEN` is missing.

**Already provisioned in Vercel** — no need to re-do setup: `OPENAI_API_KEY`, `AUTH_USERS`, and `AUTH_SECRET` are set for **Production + Preview** (marked *sensitive*, so they're intentionally absent from the Development scope and from `vercel env pull`), and a linked Blob store **`wsj-club-quizzes`** supplies `BLOB_READ_WRITE_TOKEN` to all environments. The working copies also live in the local gitignored `.env.local`. `ADMIN_USERS` is **provisioned to `anurag`** (Production + Preview, and in `.env.local`), so `/admin` is unlocked for that teacher login; admin is additive, so `anurag` is also a normal `AUTH_USERS` login who can take the voice quiz. The other logins (`anusha`, `samaira`, `arjun`, `mehar`) are students — voice quiz only. (To change teachers, edit the comma-separated `ADMIN_USERS` in both scopes and `.env.local`, then redeploy.) For a fresh checkout, recreate `.env.local` by hand (the sensitive values aren't pullable) — at minimum `OPENAI_API_KEY`, `AUTH_SECRET`, an `AUTH_USERS` from the hash script, `ADMIN_USERS`, and `BLOB_READ_WRITE_TOKEN` (pullable via `vercel env pull`).
